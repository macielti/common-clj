# Agent Notes

## Project shape

- This is a single Clojure/Leiningen library (`net.clojars.macielti/common-clj`), not an application or workspace. Public namespaces live under `src/common_clj` and map to `common-clj.*`; there is no umbrella entrypoint, so require the specific namespace you need.
- Treat `project.clj` as the canonical build and dependency manifest. `pom.xml` is generated by Leiningen and ignored by Git; edit `project.clj`, not `pom.xml`.
- Run Leiningen commands from the repository root. Test CI uses Java 21 (Zulu) and Clojure 1.12.4.
- Integrant components use `ig/init-key`/`ig/halt-key!` methods under `common-clj.integrant-components.*`; requiring the component namespace is what registers its methods.

## Code conventions

- Use `defn` for ordinary helpers, `defn-` or `^:private` for implementation-only helpers, and `s/defn` when a function has explicit Schema input/return annotations.
- Prefer destructuring for map-shaped arguments. Keep the whole request/context with `:as` when it is needed; use `[_ {:keys [...] }]` for Integrant lifecycle methods.
- For nested request contexts, destructure the relevant request keys and retain the whole context with `:as` only when it is needed, for example `[{{:keys [json-params]} :request :as context}]`.
- Keep dependent bindings in one `let`; avoid nested `let` forms when the values are related. Use persistent map literals instead of `array-map`, and keep scalar arguments named/typed instead of wrapping them in a map solely for destructuring.
- Use `_` for unused Integrant lifecycle arguments and underscore-prefixed names for intentionally unused values.

## Development and testing

- Resolve dependencies with `lein deps` before verification.
- Run the full suite with `lein test`. The `:dev` profile includes `test/unit`, `test/integration`, and `test/helpers`; there is no separate unit or integration task.
- Put unit tests under `test/unit` and integration tests under `test/integration`; the dev profile replaces the default test paths, so keep new tests in those directories to have them run by default.
- Run one test namespace with `lein test common-clj.schema.core-test`, or one test var with `lein test :only common-clj.schema.core-test/loose-schema-test`.
- Prefer `s/deftest` and `matcher-combinators.test/match?` for new tests where appropriate. `.lsp/config.edn` maps `schema.test/deftest` to `clojure.test/deftest`.
- For Integrant tests, define a `system-components` map with namespaced keys (and `ig/ref` where the graph has dependencies), initialize it with `(ig/init system-components)`, exercise the initialized component, and call `(ig/halt! system)` in a `finally` block so cleanup still runs when an assertion fails.
- Use `lein check` for a namespace/compile check.
- Check style and diagnostics with `lein lint`; it runs `clean-ns --dry`, `format --dry`, then `diagnostics`. Formatting and namespace rules are in `.lsp/config.edn`.
- Apply namespace/format fixes with `lein lint-fix` (or `lein clean-ns-fix` / `lein format-fix`), inspect the resulting diff, and rerun `lein lint`. The fix alias does not run `diagnostics`.
- `lein repl` opens in `common-clj.schema.core` because it is the configured `:repl-options :init-ns`.
- Use `lein antq` only for intentional dependency updates, then review the `project.clj` diff and rerun verification.
- Start with the narrowest relevant test, then run the relevant verification commands and inspect the diff before proposing a change.

## Gotchas

- The `:dev` profile replaces `resources` with `test/resources`, and config tests use paths such as `test/resources/config_test.edn`; run from the repository root.
- `traceability-test` starts an embedded server on `0.0.0.0:8080`; port 8080 must be free for the full suite. The current integration tests do not require Docker or an external database.
- `lein lint` can emit existing informational `clojure-lsp` `unused-public-var` diagnostics; use its exit status rather than treating baseline output as a failure.
- Some documentation is historical or stale: `doc/time.md` contains old namespace names, and `doc/components/http-client.md` describes a component no longer present in `src/`. Verify APIs against `src/`, tests, and `project.clj` rather than copying the docs.
